# Project Summary: AJSM Gym Management System

## High-Level Purpose
The AJSM Gym Management System is a comprehensive, multi-role web application designed for **Raudat ul Ikhwaan**, under the **Al Jamea Tus Saifiyah** (Marol Campus). It facilitates gym operations, student fitness tracking, attendance management, and gamified progression for a specialized gym environment.

The system supports several user roles:
- **Students:** Track fitness progress, log workouts, manage leaves, and earn achievements.
- **Trainers:** Manage student sessions, log fitness tests, and oversee daily gym activities.
- **Staff:** Manage enrollment, waiting lists, attendance, and leave requests.
- **Evaluators:** Provide expert feedback and grading on student fitness records.
- **Admins:** System-wide management, user administration, and batch control.

## Recent Milestones (March 2026)
- **Workout Planner V2 Core:** Fully transitioned from legacy JSON-based planning to a normalized 6-table relational schema for granular tracking.
- **Dynamic Exercise Library:** Replaced 800+ lines of static HTML with a cached, API-driven exercise accordion including video tutorial links.
- **In-Session Logging (Phase 3C):** Launched real-time performance logging, allowing students to record sets, reps, and weight during their sessions.
- **PR Detection Engine:** Automated backend logic to detect and flag Personal Records (PRs) based on historical performance data.

## Tech Stack
### Backend
- **Runtime:** Node.js
- **Framework:** Express.js
- **Database:** Microsoft SQL Server (MSSQL) using the `mssql` package.
- **Authentication:** Session-based (`express-session`) with `bcrypt` for password hashing.
- **Caching:** In-memory caching via `node-cache`.
- **Utilities:** `moment-timezone` for date handling, `multer` for file uploads, `node-cron` for background tasks.

### Frontend
- **Build Tool:** Vite
- **Architecture:** Single-page feel using static HTML files and modular JavaScript (`public/js/student-modules`).
- **Styling:** Vanilla CSS, Bootstrap 5, Animate.css.
- **Visualization:** Chart.js (Progress charts), Cal-heatmap (Activity heatmap), D3.js.
- **UI Components:** SweetAlert2 (Modals), DataTables (Tables), Choices.js (Selects), Flatpickr (Date picking).

## Entry Points
- **Backend:** `server.js` - Configures Express, middleware, routes, and starts the MSSQL connection.
- **Frontend:** `public/index.html` - The main landing page.
- **Build Output:** `dist/` - Generated by `npm run build`.

## Environment Variables Required
The system relies on a `.env` file (or system environment variables) for the following:
- `DB_USER`: MSSQL Database username.
- `DB_PASSWORD`: MSSQL Database password.
- `DB_SERVER`: MSSQL Server address (e.g., `fittracker.mssql.somee.com`).
- `DB_NAME`: MSSQL Database name (e.g., `fittracker`).
- `SESSION_SECRET`: A secure string for signing session cookies.
- `INTERNAL_SECRET`: Used for securing internal maintenance routes (e.g., `x-internal-secret` header for achievements).

## Deployment Model
- **Hosting:** Currently configured for **Render.com** (as seen in CORS settings).
- **Static Assets:** Served from the `dist/` directory after being built by Vite.
- **Database:** Hosted externally (e.g., Somee.com or similar MSSQL provider).
